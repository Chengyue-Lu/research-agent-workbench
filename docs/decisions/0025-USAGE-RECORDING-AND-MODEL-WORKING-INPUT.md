# ADR-0025：运行用量记录与模型工作输入

状态：2026-10-10 人类明确授权方向及 docs-only task-definition；提交本 PR 审阅。设计与实现分别接受，当前实现覆盖见 [STATUS](../STATUS.md)。

## 问题与输入

人类要求将任务规划增补和预算整改一起落文档：保留实际消耗记录，取消通用经济额度限制，模型不携带额度/余额上下文或承担预算管理。Codex 机制对照归 Issue #18，不进入任务计划。

固定核验输入为 develop `67a7c5f6a0c3495f1ad583864d87b25f5bf892e2` 和 PR140 候选 `766bf45ccde4637684e2100480e9f1577cc61662`。现行 Task/Policy/View 有必需非空 budget，View 取最小交集，Host/Session 判定超限；PR140 的角色 baseline 要求预算不足停止，模型请求包含完整 Task。当前行为与新方向的差异需要明确迁移，不能只删除文档中的词。

## 决定

1. **实际用量属于可观察事实。** 程序关联请求、意图、Task、Attempt、父子和 Provider/Tool 的实际 token、调用次数、耗时、可得费用及 failed/unknown。零调用、未知和已测量分别表达，不猜测成本、不把缺失填零。记录支持人类查看与工程评价，不自动形成执行配额。
2. **通用执行不要求经济预算。** 新路径不要求项目/Task/sub-task 额度，不实施余额预检、预占、超额停机或 unknown holds。账本缺失、费用未知和 token 未报告单独成为记账缺口，不能单凭它们中止工作、否定有效交付或自动重试。响应、工件或执行证据缺失仍按自身义务判断。
3. **模型只消费任务相关工作输入。** 显式投影职责、目标、获准材料、权限、必要决定/反证、交付/检查及真实停止条件；完整控制对象、内部执行参数和用量账本由程序持有。入口、main、child、Guide、短程、维护与解释都不默认注入经济额度、余额、预占或模型自估消耗职责。模型按工作需要提出方向、子任务和修复，不生成预算字段。用户明确询问消耗时可提供相应用量记录；任务原文中的费用讨论不因字段过滤被删除。
4. **技术条件与治理边界独立。** 模型真实窗口、接口必需输出参数、传输超时和实际运行能力由程序适配，不用演示常量伪装技术上限。完成、明确取消、实际失败、权限/数据/输入版本/供给资格与适用 Human Gate 保持；这里不授予新权限、Supply selection、fallback、Claim 接受或 Topic 5 恢复。
5. **原研究路径和有限增量保持。** 多意图独立状态/结果；工作集先读取、维护后增加；活跃任务可选单层方向组织，反馈仍经所属 main。运行事实与只读前端独立交付，模型解释停用不影响显示。记忆资料不获得指令或科学决定权。

## 实施接点

[TASKS](../TASKS.md) 定义 M6-013 的跨契约迁移和 M6-011 的能力/记账增强。M6-013 发布显式新版本的 Task/Policy/View/Host/Session 和模型工作输入投影；producer 程序装配内部元数据，模型输出不必符合旧版 budget 必填字段。仅改 Prompt、传一个极大额度或隐藏预算字段都不算迁移完成。

M1-013/M6-012/M3-011 不等待增强预算/记账系统；M11-010 消费迁移的实际新版本输出，才能验收无额度默认产品路径。原桥接 M1-010/M2-009/M11-008 继续按实际使用的支持版本独立验收，并明示覆盖与缺口，不因新记忆/前端/分支追加前置，也不把旧预算行为证据当新默认路径证据。

完整任务、具体硬依赖和验收只由 TASKS 维护；实施关系见 [REALIZATION_PLAN](../workstreams/chengyue-lu/RWB-CHAIN-TASK-DEFINITION/REALIZATION_PLAN.md)。

## 版本与接受边界

旧 budget 工件、历史 grant、固定评价条件与已接受测试按原版本保留，不能通过新解释静默松绑；旧 DONE 不改写。新旧版本显式选择、迁移器及消费者闭包要求见 [预算契约迁移](../compatibility/BUDGET_CONTRACT_MIGRATION.md)。现有真实 API 测试的授权范围/停止条件仍按具体 grant，不能从产品方向推出新付费授权。M5 冻结对照参数不是通用产品必需配额。

本次修改不改代码、Schema、Registry、实际 API 配置、远端门禁或旧测试证据。人类已授权文档与 PR，merge/release、真实项目及科学接受保持各自决定。对抗性验收覆盖无额度执行、模型请求投影、用量 unknown 但有效交付、旧版预算仍准确回放、权限拒绝和输入漂移拒绝；当前文档检查只验证定义/依赖/引用一致性。
