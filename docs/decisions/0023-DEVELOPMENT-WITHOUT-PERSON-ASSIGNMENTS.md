# ADR-0023：取消开发人员分工限制

状态：2026-10-08 人类明确授权的开发治理方向；文档候选 PR141，机器政策同步待 M0-008。

## 依据

本轮人类指令：

> 取消所有的负责人相关限制，目前我已承接所有主要开发任务，无需在任何开发文档中提出由谁负责什么。

旧文档把功能模块权威与固定人员维护范围混写，造成实现、测试和共享接口审查必须由某个指定人参与的限制。开发计划应由 Task、风险、允许范围和证据组织，不再用固定姓名或人员组合决定是否可以推进。

## 决定

- 现行开发文档取消人员职责表、指定人员签字前置及跨指定负责人审核要求；新的 M Task 不分配固定人名。实施时仍声明互斥写入范围，保留可见变更与检查记录。
- PR/CI、任务依赖与风险审查继续适用；最终合并和发布按人类实际指令执行，不从开发授权推导 merge/tag/publish 授权。
- Human、Research Control/Resolver、Runtime、Tool 的功能权限保持各自契约；Skill/来源/Claim 的适用接受条件继续保留。取消开发人员限制不授予 Agent 人类决定权。
- ADR-0012 中固定开发人员分工及 ADR-0022 中指定另一 reviewer 不可用的开发流程前置不再作为现行文档规则。其原文、历史 Task DONE、既有接受记录和 actor/授权事实保留，不能改写历史证明。
- 本 PR 仅更新 Markdown。治理器 owner 映射、PR 模板、CODEOWNERS、外部 ruleset 的调整由 M0-008 单独 feature 完成，报告修改前后实际门禁；当前在线状态不能由文档自报已取消。

## 后果与验证

功能边界仍按实际动作检查；运行记录中的授权身份字段不是开发模块分工表，本轮不改对象 Schema。历史文件可出现原维护人，但现行导航须说明不构成未来开发限制。验证范围为 active 文档引用/任务定义与历史不变性；机器实施还需治理正反测试、实际远端状态和硬门禁保留证据。
