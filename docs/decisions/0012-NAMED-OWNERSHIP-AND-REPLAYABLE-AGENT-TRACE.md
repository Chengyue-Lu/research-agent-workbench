# ADR-0012：实名责任与可回放 Agent Trace

状态：Accepted

日期：2026-08-14

## 背景

原文档使用“本侧”“同伴侧”和工作流名称表达维护关系。该写法在两人以上协作、人员变更、PR 评审或故障追责时无法回答谁应作决定。原有 Worklog 只保留关键摘要，也不能重放 Agent 之间究竟传递了什么，因此难以判断问题来自 Task、路由、上下文、Handoff 改写还是执行实现。

完整保存所有历史正文又会与上下文克制冲突，并可能引入敏感数据、Git 体积和审阅成本问题。

## 决定

1. 技术范围继续使用工作流名称，但每个工作流、Task、ADR、PR 和 Handoff 必须绑定实名责任人；当前 Mode–Skill 负责人为路诚钺，API Execution 负责人为黄毅。
2. 每个 Agent 使用稳定 `actor_id`，并绑定 `accountable_owner`。Agent、模型或窗口名称不能替代人的责任。
3. 每个 Attempt 建立一个文件式 Archive，保存所有 Agent 间实际可见的传递内容、可观察的工具/命令调用与结果、文件读取/写入事件、正式和中间输出、检查、范围变化、Handoff 和状态事件。
4. 发送方在运行时允许的情况下先写消息信封再发送；接收方在继续处理前保存收到的可见内容。无法原子捕获时记录 capture gap。
5. Worklog 保留为人类可读摘要，但不再被视为完整过程记录。
6. 留存不意味着默认加载：Agent 可读 `INDEX.yaml` 元数据，只能读取 Assignment、允许集和显式引用的消息/工具正文；排障与评估由人工或新 Task 扩大读取范围。
7. 不保存隐藏 Chain-of-Thought、密钥、认证头和政策禁止保留的原文。任何删减都写明原因、范围与可用哈希/定位信息。
8. 完整 Trace 是否进入 Git、保留多久以及能否外传，由 Project Protocol 的数据政策决定；敏感或大型 Trace 默认只保存在项目工作区。

## 后果

优点：

- 能重放 Agent 协作、检查摘要是否失真，并定位冗余 Handoff 和无效 review；
- 开发责任不再依赖聊天背景或“我们”是谁；
- 主 Agent 不必加载完整历史，索引与实际正文解耦。

代价：

- 需要定义消息信封、actor registry、索引和 capture-gap 检查；
- 完整 read/tool event ledger 会增加存储，需要避免复制已有不可变大文件；
- 运行适配器需要实现写前捕获或可验证的导出；
- Trace 可能包含敏感或大体积内容，需要保留和脱敏策略；
- 消息完整不等于科研结论正确，不能把 Trace 数量作为质量指标。

## 不采用

- 只保留 Worklog：过度依赖摘要，无法校核 Agent 间原始传递。
- 默认把全部 Trace 加载给主 Agent：直接制造上下文过载和污染。
- 用工作流、模型或 Agent 名称代替负责人：无法形成稳定的审批与维护关系。
- 强制把所有 Trace 提交 Git：不适合敏感、大型或高频运行数据。
