# Execution and input boundaries

Implementation workstream for Issue #87; Audit ID `TEST-PERF-002`, accountable
owner Chengyue-Lu, risk R2. The user authorized starting this stage on September
27 after the M14, M5 and documentation development consultations.

## Problem and intended behavior

The current selector adds every opaque consumer to an ordinary changed Python
seed. A fixed Git identity query and an unknown executable can therefore create
the same conservative edge. There are also genuine broad inputs: package-wide
source identity, schema catalogs, resource integrity and public composition roots.
An accurate model must explain these separately and retain their required proofs.

Ordinary functions should not require individual reduction declarations. Imports
and recognizable input operations should supply facts automatically; explicit
contracts belong at the smaller set of execution and I/O boundaries. An observed
fixed target is not proof of a complete input closure or permission to skip tests.

## Implementation sequence

1. Extend the existing dependency fact extraction and contract report with
   source-bound operation evidence. Distinguish execution, content, directory
   membership, identity and output observations, including unresolved context.
   Reuse the existing AST pass and immutable source cache. The first slice retains
   the accepted graph and worker obligations while making fallback causes auditable.
2. Validate boundary facts with independent source reconstruction, adversarial
   changes and unchanged-selection controls. Activation requires accepted rules
   and the existing independent authority floor, not candidate self-attestation.
3. Separately remove verified test-organization coupling: pure constants/builders,
   dynamic loaders, focused unit tests and complete protocol integration targets.
   Preserve test identity and actual cold-process/Tool/Git behavior during migration.
4. Measure process coverage collection and fixture initialization independently of
   selection. Retain distinct entry-point and protocol assertions; collection-only
   or previously executed evidence is not a new producer timing result.
5. Treat any reduction in package/catalog identity scope as a separate contract
   change, with the same refusal conditions, reviewed failure timing and an explicit
   owner for the complete integrity proof.

This sequence implements the existing [acceptance matrix](CI_REPLAN_ACCEPTANCE.md).
M14 and M5 are regression samples, not names granting selection exemptions. A
further business sample must be held out from rule development before reduction
is claimed generally.

## First-slice acceptance

- Every operation observation binds exact source bytes and a callsite, with its
  interpretation and unresolved target, environment, import and root dimensions.
- Git identity, content and tree operations are not conflated. Fixed Git commands
  may read full contents or invoke configured mechanisms; Python entry points
  still depend on their complete imports, environment and resources.
- Changes to aliases, wrappers, keywords, dynamic arguments and invocation context
  cannot be presented as the same proven operation. Unrecognized cases remain
  unknown; source identity and directory-member changes remain visible.
- Existing selected tests, B/C obligations, coverage, smoke and authority behavior
  remain unchanged by the explanatory facts. Report fields cannot authorize skips.
- Faults in source binding, omitted observations or altered classifications must
  be rejected by reconstruction checks. Relevant fixtures include unknown targets
  and legitimate fixed operations, not only happy-path examples.
- Tests and an explicit parser/analysis cost measurement accompany the feature.
  No speedup is claimed from the number of observations or selected modules.

## Quality and review boundary

Global90, critical95/90, changed100/100, dual-Python behavior, fixed aggregate
gates, source authority and fresh integration evidence remain in force. No
cross-commit test-result reuse is activated. New implementations are published
as independently reviewable Draft PRs; acceptance and merge are separate decisions.

PR #101 remains an independently reviewed candidate. Its proposed safety and
diagnostic contracts are not treated as already accepted by this workstream.
Results and raw evidence will be recorded under their actual implementation and
execution identities. See the [risk ledger](RISK_LEDGER.md).

## Report representation

The contract report uses schema5. Snapshot consumer records retain Git commit,
object, mode and fallback flags. Equal consumer paths and source bytes share one
source table; its ordered call rows name their columns explicitly. Detail records
are content-addressed. Every call remains represented, including unclassified
ordinary calls, removed old-side calls and parse failures. Unclassified argument
context is omitted from display; the full call AST and source hashes still bind
it. This omission never means that the call has no inputs or uses default context.

The verifier reconstructs the complete catalog and edge references from the Git
snapshots. Re-signing hashes cannot legitimize missing calls, reordered columns,
unreferenced records, altered source bindings or changed classifications. Known
command shapes retain unresolved executable, import, environment and resource
dependencies. Argument and environment payloads are represented by shape and
hash; the report does not copy their source literals.
