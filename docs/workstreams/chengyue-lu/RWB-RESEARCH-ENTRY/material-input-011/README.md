# 获准材料的实际消费

本切片接通 M1-010 的材料读取部分：人类列明的原件、来源记录与本次派生文本，进入 intake 和冻结角色执行时使用同一组精确引用。来源记录提供关联事实；读取权仍来自 Task。Task 的其余义务及 M2-009/M11-008 保持进行中。

## 测试对象与交付

| 模块 | 输入 | 实际产物与检查 |
| --- | --- | --- |
| 材料读取 | Task 中的原件、canonical admission sidecar、选中派生项 pins | 同批字节核验的 UTF-8 文本与 `material_provenance`；校验原件关联和派生关系，只打开获准文件 |
| 需求入口与控制编译 | 上述快照、明确的控制 ceilings、注入的离线模型响应 | 真实程序编译及保存控制草稿；模型删掉必需 sidecar 时拒绝草稿并保留已经发生的调用与用量 |
| 包内工厂 | 实际 Task 与原有冻结供给输入 | 写入角色目录前检查材料闭包；形成原有 Bundle / View 与角色记录 |
| Driver 与 Host | 冻结输入、实际角色请求 | Trace 记录读取的 pins；在最终 Provider 边界重新检查材料，拒绝回调之后的漂移，区分请求捕获与实际调用 |
| child → fresh main | 实际 child 工件及正式 Handoff | 主消费者核验 Handoff 并继续；成功链的 Receipt 由独立冷消费者验证 |
| M6-013 工作输入候选 | 已验证 Task 与明确工作字段 | 独立的 0.2.0 白名单投影；只验证纯投影，尚未替换角色请求或旧 Runtime |

完整桥接采用真实包内消费者及注入的离线 Provider。它验证文件、请求、产物和消费关系；本切片没有新增真实 API 调用、科研案例或来源科学质量评价。

## 边界与后续

未选的派生项即使列在 sidecar 内，也不会被读取。缺少闭包、哈希漂移、inbox 引用以及伪装来源区的大小写或链接别名均须阻断。当前支持 UTF-8 文本，沿用现行版本的文本大小限制；多格式和大型材料消费由 M3-010 继续实现。

最终派发前已捕获请求但没有实际调用的失败，保留零调用事实和 Trace。旧 generic closeout 对此分支的捕获计数与调用计数尚未完全分离，可能形成 incomplete closeout；不补造 Receipt。该缺口列入 [验证记录](VERIFICATION.md)，后续 M11/M6 消费者接合需处理。

M6-013 首切片来自独立并行候选，迁移范围及未接消费者见 [Migration](../../M6-013-WORKING-INPUTS-SLICE-001/MIGRATION.md)。现行材料快照新增 provenance，而纯投影尚不接此扩展字段；后续需明确版本化材料槽，随后串行迁移角色请求与 Runtime。它不构成无预算执行证据。

执行范围见 [Task Packet](TASK_PACKET.md)，结果和原件定位见 [验证记录](VERIFICATION.md)。实现、定义和实际运行各自保留来源身份，候选分支不计作 develop 已合并支持。
